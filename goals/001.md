# Goal 001: Level 4/5 portable snapshot inventory and graduation map

## Objective

Make the portable snapshot ladder the center of roadmap and product discussions.
Machinen is trying to graduate toward:

- **Level 4** — `level-4-kernel-resource-reconstruction`: kernel resources have
  explicit descriptor, recreate, and replay semantics.
- **Level 5** — `level-5-cross-arch-process-continuation`: live process execution
  state is translated across ISAs without source-ISA emulation.

**Level 3 is a stop gap.** Treat `level-3-runtime-aware-continuation` as
technical debt unless the row names its migration path to Level 4/5. Level 1/2
can remain supported by design when the product is intentionally semantic
restart/semantic continuation rather than process continuation.

## Non-negotiable claim rules

1. Always separate `productSupport` from `implementationLevel`.
2. `migrationCompleted=true` means the named verifier passed; it does **not**
   imply product support.
3. Product success cannot be claimed through source-ISA emulation, sidecar output,
   metadata-only success, or raw cross-ISA checkpoint replay.
4. Native/process proof rows remain `native/process-proof` unless a
   future change routes them through public product verbs.
5. Refusal rows remain `unsupported` with `migrationCompleted=false`.
6. Level 3 rows must be labeled as debt or explicitly scoped as supported
   Level 1/2 by design.

## Level 4 first-class inventory

Level 4 is the missing kernel-resource reconstruction layer between runtime-aware
safe-point proofs and Level 5 process continuation. Each item below needs a
portable descriptor, target-native recreate/replay procedure, verifier, and
fail-closed refusal codes before it can count as Level 4 support.

| Level 4 area           | Required descriptor/model                                                                                                                                                     | Current status                                                                     | Graduation requirement                                                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Raw/ping sockets       | ICMP id/sequence, destination, route, capabilities, ping group range, receive queue, in-flight packets                                                                        | Ping product is Level 2 semantic continuation; raw socket state refused            | Promote only with descriptor that recreates socket/capability/namespace and validates empty/in-flight queue policy; otherwise keep Level 2 semantic ping by design. |

## Runtime/workload support map

- **Level 4/5 relevant** — evidence or requirements directly exercise kernel
  resource reconstruction or process continuation.
- **Level 3 debt with migration path** — useful runtime-aware proof, but must
  move down into Level 4 descriptors or up into Level 5 process translation.
- **Supported Level 1/2 by design** — intentionally semantic product
  support; not a Level 4/5 claim.
- **Unsupported Level 0 refusal** — fail-closed unsupported state.

## Graduation requirements by runtime/workload

### Node

Node graduates toward Level 4/5 when all relevant libuv/kernel resources and V8
process state are explicit:

- Level 4: TCP/UDP sockets, listeners, active connections, pipes, event loop
  readiness, timers, child/IPC handles, fs watchers, credentials/namespaces, and
  partial transfers have descriptors and target-native recreation.
- Level 5: V8 heap/code/stack/register state, native addons, worker threads,
  signal/TLS/SIMD/FPU/thread policy, and return chains have target-native
  translation and verifier coverage.
- Product graduation requires public `machinen snapshot` / `machinen restore`
  with no hidden runtime-specific flags.

### JVM

JVM graduates only with an explicit JVM profile:

- safepoints and thread states are controlled;
- Java and native stacks have frame/unwind descriptors;
- JIT/code cache and class metadata are target-materialized or refused;
- JNI/native libraries have ABI/provenance policy;
- monitors, signals, TLS, FPU/SIMD, sockets, timers, and file descriptors are
  Level 4/5 modeled;
- unsupported runtime/JIT/thread states remain refusals.

### Go

Go graduates only when runtime scheduler state stops being opaque:

- goroutine stacks, scheduler queues, netpoller, timers, channels, cgo, TLS, and
  signal state have descriptors or refusals;
- sockets/readiness/partial transfers are Level 4 modeled;
- Level 5 process/thread/register/stack materialization is target-native;
- clean static service restart can remain Level 1 by design.

### Python

Python graduates only when interpreter and C-extension boundaries are explicit:

- Python frames, GIL/thread state, asyncio/selectors, signals, sockets, file
  descriptors, C extension ABI/state, and module provenance are modeled;
- Level 4 handles kernel resources rather than hiding them behind a runtime
  adapter;
- Level 5 handles native stack/register/memory/code if process continuation is
  claimed;
- clean service restart can remain Level 1 by design.

### Databases

Databases graduate only when logical restore is no longer standing in for process
or kernel state:

- active clients/sockets, transactions, WAL/redo/AOF/journals, locks, mmap,
  shared memory, replication, plugin/extension state, file offsets, fsync
  boundaries, and dirty host-mounted state are modeled or refused;
- quiesced logical restore can remain product/proof semantic restore, but must
  not imply Level 4/5;
- live database process continuation requires both Level 4 resources and Level 5
  process translation.

### Ping

Ping's current product support is intentionally Level 2. It graduates to Level 4
only when raw/ping socket state is modeled:

- raw or datagram ICMP socket descriptor;
- uid/gid/capability/ping group range policy;
- network namespace, route, and destination policy;
- identifier/sequence/counters tied to socket state;
- receive queue and in-flight packet ordering;
- active `recvmsg` and partial transfer policy;
- target-native verifier that proves recreated socket behavior.
