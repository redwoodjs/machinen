# Goal 021 — Node adapter: single-thread V8/libuv HTTP profile

## Status

Historical proof-only runtime-profile work. This does not claim arbitrary Node or product support, and it must not be used as the product route for Level 5. Goal 023 supersedes runtime-profile productization with a captured-process-state track.

## Purpose

Build a proof-only Node/V8/libuv adapter on top of the generic Level 5 substrate: a narrow, non-app-specific HTTP profile for vocabulary, artifacts, and refusals.

This is not arbitrary Node restore and is not the forward product mechanism. Any future product Level 5 claim must be based on captured source process state and target-native reconstruction, not this runtime profile.

## Historical proof profile

Profile name:

`node-v8-libuv-single-thread-http-v1`

Initial supported shape:

- one Node process;
- single thread;
- target-native Node available on restore;
- HTTP server/listener represented by Level 4 TCP listener descriptor(s);
- no active request at capture;
- no active TCP streams;
- no worker threads;
- no native addons;
- no inspector/debug session;
- no active syscalls/restart blocks;
- bounded V8/libuv state that the adapter explicitly captures and restores.

The profile was runtime-level rather than quickstart-app-specific. That distinction is useful for avoiding selected-state shortcuts, but runtime-level profiles are still not an acceptable product path for Machinen Level 5.

## Capture responsibilities

The Node adapter must capture enough checked runtime state for target-native continuation, including:

- Node executable/runtime identity;
- argv/env/cwd and entrypoint/module identity;
- selected V8 heap roots/state supported by the profile;
- libuv handle inventory;
- HTTP listener descriptor(s);
- timers/async handles only when supported by the profile;
- refusal facts for unsupported neighbors.

The adapter must not infer arbitrary V8 heap or native stack state as supported until explicitly modeled.

## Restore responsibilities

The Node adapter must restore by starting/entering target-native Node code on the destination architecture, then:

- recreate supported Level 4 resources;
- load the same app/module or continuation entry under the adapter contract;
- inject/restitch captured supported runtime state before accepting traffic;
- resume the event loop;
- produce target-side verifier output from the actual target Node runtime.

## Required refusals

Fail closed for:

- arbitrary V8 heap/native stack continuation;
- native addons;
- worker threads;
- inspector/debug state;
- active requests;
- active TCP streams;
- active syscalls/restart blocks;
- unsupported timers/async handles;
- unsupported module/runtime state;
- missing target-native Node;
- any source-ISA emulation, sidecar output, or metadata-only shortcut.

## Acceptance criteria

- The Node profile is implemented as a proof-only Level 5 runtime adapter.
- `machinen snapshot` writes a profile artifact for selected Node bundles.
- `machinen restore` routes selected Node bundles through the adapter and keeps unsupported cases refused.
- Target-side verifier output proves target-native Node execution for the harness.
- Status fields remain honest: proof-only, with product support blocked until a captured-process-state implementation exists.
- Tests cover happy-path proof planning plus each stable refusal family.
