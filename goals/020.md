# Goal 020 — Generic Level 5 runtime adapter substrate

## Status

Completed in this change as the generic Level 5 adapter substrate and registry. The existing Node Level 5 proof path is adapter-routed, but this goal does not claim arbitrary runtime or Node product support.

## Purpose

Move Level 5 from proof-specific Node wiring toward a reusable cross-architecture continuation substrate. The substrate must not be app-specific. It should define the common public snapshot/restore path, artifact envelope, restore planning, verifier evidence, and fail-closed refusal behavior that runtime adapters plug into.

Level 5 means target-native continuation across architectures. It must not accept source-ISA emulation, sidecar output, metadata-only success, or raw vmstate replay as success.

## Runtime adapter contract

Introduce a generic adapter interface for runtime families, shaped around these operations:

- `detect(process | bundle)` — identify the runtime/profile and whether the adapter owns the bundle;
- `quiesce(process)` — prove the process is at a safe capture point or return stable refusals;
- `capture(process)` — record runtime state, process context, and resource descriptors;
- `validate(capture, target)` — reject unsupported source/target pairs and unsafe neighbors;
- `planRestore(capture, target)` — build a target-native restore plan;
- `restoreTargetNative(plan)` — launch/enter target-native runtime code;
- `verify(result)` — prove continuation came from the target-side runtime;
- `refuse(reason)` — produce stable refusal summaries with `migrationCompleted=false`.

The common substrate owns:

- public `machinen snapshot` / `machinen restore` dispatch;
- artifact naming and versioning;
- source/target architecture metadata;
- Level 4 resource descriptor composition;
- target-native verifier summaries;
- product/proof status fields;
- stable refusal envelopes.

## Required status fields

Every Level 5 artifact must distinguish:

| Field                   | Meaning                                                          |
| ----------------------- | ---------------------------------------------------------------- |
| `evidenceStatus`        | proof/support/refusal status for the row                         |
| `productSupport`        | whether users can rely on this as product support                |
| `implementationLevel`   | implemented substrate/profile level                              |
| `graduationTargetLevel` | target level, normally `level-5-cross-arch-process-continuation` |
| `migrationCompleted`    | true only when the actual supported workload continued           |

Proof-only rows must not imply product support.

## Required refusals

The substrate must make unsupported states fail closed with stable codes, including:

- unsupported runtime family;
- unsupported runtime profile;
- missing target-native runtime;
- source/target architecture pair unsupported;
- source-ISA emulation requested or detected;
- sidecar output shortcut requested or detected;
- metadata-only success attempted;
- active syscall or restart block;
- active TCP stream or in-flight network I/O;
- unsupported thread state;
- unsupported kernel resource;
- unsupported runtime heap/stack state.

- A `Level5RuntimeAdapter` interface exists in runtime/CLI code.
- Public snapshot/restore can dispatch through the generic Level 5 adapter registry.
- Existing Node Level 5 proof behavior is represented as an adapter or adapter-compatible path.
- Checked docs/artifacts describe the substrate without claiming product support for unsupported runtimes.
- Tests cover adapter selection, refusal envelopes, and proof-only status preservation.
