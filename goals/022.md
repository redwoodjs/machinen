# Goal 022 — Real cross-arch quickstart fixture

## Status

Completed as a selected-state reconstruction harness proof, not Level 5 product support. The harness can capture quickstart-style counter state, restore it into target-native Node, and serve the continued first target request as `{ "count": 3 }`, but it uses the app-specific `node-http-counter-selected-state-v1` descriptor. Therefore it remains `productSupport=not-yet-supported`, `implementationLevel=not-implemented`, and `migrationCompleted=false`.

## Purpose

Prove the Node Level 5 adapter with the public quickstart workflow across architectures. The quickstart counter must continue on the target architecture using target-native Node and actual captured workload state.

Target workflow:

```sh
# source host, for example Mac/arm64
machinen boot --name counter -p 3000:3000 ./counter.tar.gz
curl localhost:3000 # { "count": 1 }
curl localhost:3000 # { "count": 2 }
machinen snapshot counter ./counter.snap

# target host, for example Proxmox/amd64
machinen restore ./counter.snap -p 3000:3000
curl localhost:3000 # { "count": 3 }
```

## Required evidence

The checked artifact must show:

- source architecture;
- target architecture;
- observed source-side counter before snapshot;
- observed target-side counter after restore;
- target runtime is Node;
- output came from target-native Node execution;
- no source ISA emulation;
- no sidecar output;
- no metadata-only success;
- the public `machinen snapshot` / `machinen restore` verbs were used.

## Product/support status

This goal must not claim product support. It is a harness proof because it uses app-specific selected state. Proper Level 5 is tracked in Goal 023 and requires captured source process/runtime/native state reconstruction without runtime profiles, checkpoint hooks, or selected-state descriptors.

## Required refusals

The quickstart fixture must preserve the Node adapter refusals for unsafe neighbors:

- native addons;
- worker threads;
- inspector/debug state;
- active syscalls/restart blocks;
- active TCP streams;
- active requests;
- arbitrary V8 heap/native stack continuation;
- unsupported V8/libuv state;
- missing target-native Node.

## Checked evidence

- Runtime profile/state model: `packages/runtime/src/node-level5-http-profile.ts`
- CLI adapter restore path: `packages/cli/src/level5-runtime-adapters.ts`
- Documentation: `docs/snapshot/node-level5-real-cross-arch-quickstart-fixture.md`

## Acceptance criteria

- A cross-architecture checked summary exists for the quickstart fixture.
- The target-side verifier observes `{ "count": 3 }` after restoring from a source state that observed `{ "count": 2 }`.
- Restore output comes from target-native Node, not source emulation, a sidecar, or metadata-only replay.
- Public restore may succeed for the harness, but summaries must still report `productSupport=not-yet-supported`, `implementationLevel=not-implemented`, and `migrationCompleted=false`.
- Unsupported variants refuse with stable codes and `migrationCompleted=false`.
- Docs update the quickstart cross-architecture wording to point to this harness proof without calling it Level 5 product support.
