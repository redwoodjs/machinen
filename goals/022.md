# Goal 022 — Real cross-arch quickstart fixture

## Status

Planned.

## Purpose

Prove the Node Level 5 adapter with the public quickstart workflow across architectures. The quickstart counter must continue on the target architecture using target-native Node and actual captured workload state.

Target workflow:

```sh
# source host, for example Mac/arm64
machinen boot --name counter -p 3000:3000 ./counter.tar.gz
curl localhost:3000 # { "count": 1 }
curl localhost:3000 # { "count": 2 }
machinen snapshot counter ./counter.snap

# target host, for example Proxmox/amd64
machinen restore ./counter.snap -p 3000:3000
curl localhost:3000 # { "count": 3 }
```

## Required evidence

The checked artifact must show:

- source architecture;
- target architecture;
- observed source-side counter before snapshot;
- observed target-side counter after restore;
- target runtime is Node;
- output came from target-native Node execution;
- no source ISA emulation;
- no sidecar output;
- no metadata-only success;
- the public `machinen snapshot` / `machinen restore` verbs were used.

## Product/support status

This goal may start as a product-candidate proof and graduate only when the restore genuinely continues the captured quickstart workload through the Node Level 5 adapter.

If product support is claimed for the narrow profile, the claim must be limited to the named profile, for example:

`node-v8-libuv-single-thread-http-v1`

Do not claim arbitrary Node support.

## Required refusals

The quickstart fixture must preserve the Node adapter refusals for unsafe neighbors:

- native addons;
- worker threads;
- inspector/debug state;
- active syscalls/restart blocks;
- active TCP streams;
- active requests;
- arbitrary V8 heap/native stack continuation;
- unsupported V8/libuv state;
- missing target-native Node.

## Acceptance criteria

- A cross-architecture checked summary exists for the quickstart fixture.
- The target-side verifier observes `{ "count": 3 }` after restoring from a source state that observed `{ "count": 2 }`.
- Restore output comes from target-native Node, not source emulation, a sidecar, or metadata-only replay.
- Public restore succeeds only for the supported profile; unsupported variants refuse with stable codes and `migrationCompleted=false`.
- Docs update the quickstart cross-architecture wording to point to this supported profile once it graduates.
