# Goal 005: Phase 2b — eventfd Level 4 reconstruction

## Objective

Create the eventfd Level 4 graduation slice. eventfd is a useful wakeup and
counter primitive for runtime event loops, but this goal starts as proof and
refusal evidence, not product support.

## Status language

| Field                   | Target while this goal is in proof mode                                            |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `evidenceStatus`        | `proof` for accepted eventfd reconstruction; `refusal` for unsafe neighbors        |
| `productSupport`        | `not-yet-supported` for proof rows; `unsupported` for refusal rows                 |
| `implementationLevel`   | `not-implemented` for proof rows; `level-0-fail-closed-discovery` for refusal rows |
| `graduationTargetLevel` | `level-4-kernel-resource-reconstruction`                                           |

## Accepted descriptor shape

Start with bounded eventfd counters:

- finite counter value;
- explicit semaphore-mode policy, initially refused unless modeled;
- explicit duplicate/alias policy;
- no waiters;
- explicit readiness state;
- explicit flags and close-on-exec state;
- target-native eventfd recreation verifier.

## Refusals

Refuse fail-closed for:

- unknown waiters;
- semaphore mode until modeled;
- overflow or max counter ambiguity;
- ambiguous aliases/duplicates;
- unsupported flags;
- active read/write syscall state.

All refusal rows must keep `productSupport=unsupported` and
`migrationCompleted=false`.

## Graduation requirements

eventfd can move from proof to support only after:

1. eventfd descriptors are accepted by the public snapshot/restore path;
2. target recreation verifies counter value, flags, and readiness;
3. alias semantics are either modeled or refused;
4. all unsafe neighbors remain checked refusals;
5. Node/libuv wakeups consume the generic eventfd descriptor.

## Non-goals

- No epoll ready-list support.
- No semaphore-mode product support until separately modeled.
- No implicit readiness success.
