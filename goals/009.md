# Goal 009: Phase 6 — selected Node Level 5 proof composition

## Objective

Compose the selected Node Level 5 path after Level 4 resources are explicit. This
is the first Node process-continuation target, but it remains proof evidence
until it is routed through public product verbs and all unsafe Level 5 neighbors
are refused or modeled.

## Current implementation start

The first implementation slice adds a `machinen.node-level5-proof-composition`
record for the selected `node-http-clean-root-v1-with-level4-event-loop-map`
proof path. It composes checked native/process ingredients with the Goal 008
Node event-loop Level 4 resource map, while keeping product support at
`not-yet-supported` and implementation at `not-implemented`.

The composition requires:

- register translation;
- stack and return-chain translation;
- private memory materialization;
- executable/target module materialization;
- target restore loader;
- Goal 008 Level 4 event-loop resource map;
- target-native verifier evidence.

It also records non-product refusals for TLS/rseq, SIMD/FPU, signal frames,
active syscalls, multi-thread state, unsupported mappings, unsupported kernel
resources, native addon ABI state, inspector/debug state, unsupported V8/libuv
state, and arbitrary V8 heap/native stack continuation.

The second implementation slice adds `scripts/node-level5-proof-composition.ts`,
which emits a checked `machinen.node-level5-proof-composition` artifact at
`docs/snapshot/checked-summaries/level4-graduation/goal-009-proof-run.json`.
The runner reads the native register, stack/return-chain, memory, restore-loader,
Goal 008 event-loop map, and target-native verifier evidence before declaring the
proof record ready. It also starts public-verb routing: Node snapshots write a
proof-composition file, and `machinen restore` detects that file but refuses it
as `node-level5-proof-only-not-product` until target-side continuation is
undeniable.

## Status language

| `evidenceStatus`        | `proof` for selected native/process composition; `refusal` for unsafe neighbors    |

## Required proof ingredients

Compose the selected Node Level 5 subset from checked native/process evidence:

- register translation;
- stack and return-chain translation;
- private memory materialization;
- executable/target module materialization;
- target restore loader;
- Level 4 fd/event-loop descriptors from Goals 004–008;
- target-native verifier that proves the restored process continues without
  source-ISA emulation.

## Refusals

Refuse fail-closed for:

- TLS/rseq/SIMD/FPU state until modeled;
- active signal frames or pending signal queues;
- active syscalls and restart blocks;
- multi-thread state;
- unsupported memory mappings;
- unsupported kernel resources;
- native addon ABI ambiguity;
- inspector/debug state;
- unsupported V8/libuv state.

All refusal rows must keep `productSupport=unsupported` and
`migrationCompleted=false`.

## Graduation requirements

The selected Node Level 5 subset can move from proof to support only after:

1. required Level 4 resources are supported or explicitly bounded for the product
   subset;
2. native/process proof rows are routed through public `machinen snapshot` /
   `machinen restore` verbs;
3. target verifier proves target-native continuation, not sidecar output;
4. TLS/SIMD/FPU/signal/syscall/thread/mapping/resource neighbors are modeled or
   remain checked refusals;
5. docs name the supported Node subset and all unsupported neighbors.

## Non-goals

- No arbitrary Linux process-image continuation.
- No arbitrary Node app continuation.
- No source-ISA emulation, sidecar output, metadata-only success, or raw
  checkpoint replay.
