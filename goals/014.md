# Goal 014 — Extract generic portable restore adapter interface

## Status

Completed in this change.

## Objective

Move the ping-specific portable restore path toward a reusable adapter shape before adding more Level 4 resources.

## Adapter contract

`packages/cli/src/portable-restore-adapter.ts` defines the generic contract used by portable restore adapters:

- `detect` — identify whether a bundle belongs to the adapter;
- `validate` — load descriptors, validate target architecture and verifier state, and produce either an accepted validation or a refusal;
- `plan` — convert accepted validation into a target restore plan;
- `foregroundRestore` — run the plan in attached/foreground mode;
- `detachedRestore` — run the plan in detached/JSON mode;
- `verify` — prove the target-side continuation is alive;
- `refuse` — report stable refusal output.

## Ping adapter

Ping is now the first adapter:

- profile: `ping-level4-socket-reconstruction-v1`;
- detect: `portable-ping-socket.json` bundle marker;
- validate: existing product Level 4 ping restore validation;
- plan: descriptor path, foreground command, detached command, verifier command, and summary builder;
- foreground restore: generic foreground portable workload runner;
- detached restore: generic detached portable workload runner;
- verify: target ping PID/output check;
- refuse: existing ping refusal summary with `migrationCompleted=false`.

## Generic restore mechanics

`machinen restore` now dispatches portable bundles through the adapter registry before falling back to other restore paths. The generic helper owns mechanics that should be shared by future Level 4 adapters:

- boot target VM;
- write descriptor into the guest;
- attach foreground workload output or run detached;
- stop target VM on foreground interrupt;
- call adapter verification;
- write detached restore summary.

The ping adapter owns ping facts only: descriptor shape, commands, verifier, and refusal summary.

## Completion record

Implemented the adapter interface, registered ping as the first adapter, moved `cmdRestore` ping dispatch through adapter detection, and preserved the existing foreground/detached ping restore behavior.
