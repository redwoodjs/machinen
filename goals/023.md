# Goal 023 — Proper Node Level 5 without runtime profiles or checkpoint substrate

## Status

Completed as a first narrow proof. `pnpm run proof-node-proper-level5-proof` boots a real Node HTTP counter source VM, observes `{ "count": 1 }` and `{ "count": 2 }`, externally quiesces the source process with `SIGSTOP`, captures `/proc` state plus memory bytes for accepted mappings, classifies the state, builds a source-state translation IR, finds Node/V8/libuv/counter candidates from raw memory, starts target-native Node, materializes equivalent JS/libuv objects from raw captured memory evidence, and proves the first target request returns `{ "count": 3 }`.

This is still proof evidence unless and until a public product route and product claim registry entry advertise a supported subset.

## Non-negotiable rule

Machinen snapshot/restore must never use runtime-level profiles as a product path. Node/V8/libuv profiles may exist only as harness/proof metadata. Product Level 5 must translate captured source machine/process state into target-native continuation.

## Proper Level 5 acceptance

A proper Node Level 5 proof must satisfy all of the following:

- Input is captured source process state, not app-exported state.
- Target uses target-native Node.
- Continuation comes from reconstructed runtime/native state.
- No checkpoint/restore substrate, app checkpoint hooks, or app restore hooks.
- No app-specific counter extraction or selected-state descriptor.
- No source ISA emulation.
- No sidecar output replay.
- No metadata-only success.
- Unsupported state refuses with stable codes and `migrationCompleted=false`.

## Real track tasks

1. Inspect source Node process memory/runtime layout from captured process state:
   - `/proc/<pid>/maps` and memory permissions;
   - executable and shared-object mappings;
   - stack, heap, anonymous, JIT/code, and file-backed regions;
   - `/proc/<pid>/auxv`, status, task list, and fd table;
   - V8 isolate / heap-root candidate discovery;
   - libuv loop / handle candidate discovery.
2. Recover JS module/global state from process memory, not an app export.
3. Recover libuv loop handles from process/native state:
   - HTTP listener;
   - timers/async handles only when modeled;
   - active requests/streams refused.
4. Recreate target-native runtime objects:
   - target-native Node process;
   - target-native JS objects/state;
   - target-native libuv loop handles;
   - target-native HTTP listener.
5. Enter the target-native event loop with equivalent state.

## First real proof target

- Single-thread Node.
- No native addons.
- No workers.
- One HTTP listener.
- One simple mutable JS object/closure counter.
- Quiescent between requests.
- Target request returns `{ "count": 3 }` because reconstructed runtime/native state says the count was `2`, not because an app-specific descriptor said so.

## Explicitly not sufficient

The Goal 022 selected-state harness is not sufficient for this goal. It may remain as a public `machinen snapshot` / `machinen restore` regression smoke, but it must stay `productSupport=not-yet-supported`, `implementationLevel=not-implemented`, and `migrationCompleted=false`.

- Source process memory layout inspector: `packages/runtime/src/node-proper-level5-source-inspection.ts`
- Live source-state translation/materialization proof: `scripts/smoke/node-proper-level5-source-capture.sh`
- Public proof command: `pnpm run proof-node-proper-level5-proof`

The proof records V8 heap/page candidates, JS counter closure/global candidates, libuv/TCP listener candidates, refusal evidence, target-native materialization, and final `{ "count": 3 }` output. Proof 024 removes the prior response-string shortcut: the target loader now recovers count `2` by finding a retained V8 closure-context anchor in raw accepted memory, locating references to that heap object, decoding the nearby pointer-compressed V8 Smi context slot, and refusing if the raw context slot cannot be found. The reusable recovery helpers live in `packages/runtime/src/node-proper-level5-v8-closure-recovery.ts`.
