# Goal 002: Best bang-for-buck graduation path to Level 4/5

## Objective

Graduate Machinen toward real Level 4/5 portable snapshot support by taking the
smallest product-relevant path first:

1. **Ping Level 2 -> narrow Level 4 socket reconstruction**
2. **Pipes + eventfd Level 4 primitives**
3. **timerfd Level 4 primitive**
4. **TCP listener-only Level 4 reconstruction**
5. **Node event-loop resources**
6. **Selected Node Level 5 product subset**

The first target is **ping Level 4** because ping is already supported at
Level 2, has a narrow kernel-resource surface, and can establish the reusable
Level 4 descriptor/refusal/verifier pattern without taking on Node/JVM/Go runtime
complexity.

## Why ping first

Ping has the best cost/value ratio:

- already visible through product support as
  `ping-sequence-counter-semantic-continuation-v1`;
- small kernel-resource surface compared with Node/JVM/Go;
- clear Level 4 resource: ICMP raw/datagram socket;
- clear refusals: unread receive queue, in-flight packets, active
  `recvmsg`, unsupported route/namespace/credential state;
- can prove the core Level 4 loop: descriptor -> target-native recreate ->
  verifier -> refusal for unsafe neighbors.

This should not replace the existing Level 2 semantic ping product. Level 2 ping
remains supported by design. The Level 4 work is a new, narrower kernel
resource reconstruction proof/product candidate.

## First-class Level 4 inventory coverage

The checked graduation matrix must keep these Level 4 kernel-resource families in
scope even when the first implementation phases only accept a narrower subset:

- sockets, including ping/raw ICMP and TCP listeners;
- `epoll` interest lists and ready-list/refusal policy;
- `eventfd` counters, aliases, waiters, and readiness;
- `timerfd` clock, remaining-time, interval, and expiration state;
- `signalfd` signal masks, queued siginfo, pending signals, and active-frame
  policy;
- pipes and buffered bytes;
- ptys/TTY session and termios state;
- credentials and capabilities;
- namespaces and routes;
- queues;
- readiness;
- partial transfer state.

## Phase 1: Ping Level 4 socket reconstruction

### Descriptor fields

Define a first-class ping socket descriptor with:

- socket kind: raw ICMP or datagram ping socket;
- address family and protocol;
- destination address;
- identifier and next sequence;
- sent/received/lost counters when relevant to verifier;
- uid/gid and credential policy;
- `CAP_NET_RAW` or ping group range policy;
- network namespace identity/policy;
- route policy, initially target-loopback or explicitly bounded route;
- receive queue state, initially required empty;
- in-flight packet state, initially required none;
- active syscall state, initially required outside `recvmsg`;
- socket options required for verifier;
- artifact/provenance digests.

### Accepted first subset

Accept only the narrow subset:

- target-native socket can be recreated;
- credential/capability policy is explicit and verifier-checked;
- route/namespace is explicit and verifier-checked;
- receive queue is empty;
- no in-flight packets;
- no active `recvmsg` or partial transfer;
- target verifier proves ICMP behavior after restore;
- no source-ISA emulation, sidecar output, metadata-only success, or raw
  cross-ISA checkpoint replay.

### Stable refusals

Keep stable Level 0 refusals for:

- unread receive queue;
- in-flight packets;
- active `recvmsg`;
- ambiguous route;
- unsupported namespace;
- missing credential/capability mapping;
- unsupported socket options;
- raw socket state outside the descriptor;
- target verifier mismatch.

### Completion criteria

- `evidenceStatus` says whether the row is proof, planning, or refusal evidence.
- `productSupport` says whether the behavior is `supported`, `not-yet-supported`,
  or `unsupported`.
- `implementationLevel` names the actual supported level; Level 4 proof rows use
  `implementationLevel=not-implemented` until productized.
- `graduationTargetLevel=level-4-kernel-resource-reconstruction` only when
  target-native socket recreation and verifier pass.
- Refusal rows have `productSupport=unsupported` and `migrationCompleted=false`.
- Existing Level 2 ping product remains clearly separate.

## Phase 2: Pipes + eventfd Level 4 primitives

After ping establishes the Level 4 pattern, add small generic primitives:

### Pipes

Start with:

- exactly one read end and one write end;
- known peer lifetime;
- empty or bounded buffered bytes;
- no waiters;
- explicit fd flags;
- explicit readiness state;
- bounded verifier for read/write behavior.

Refuse unknown peers, waiters, oversized buffers, unsupported flags, and ambiguous
readiness.

### eventfd

Start with:

- finite counter value;
- no waiters;
- no semaphore mode initially;
- explicit alias/duplicate policy;
- readiness verifier.

Refuse waiters, semaphore mode, overflow, ambiguous aliases, and unsupported
flags.

## Phase 3: timerfd Level 4 primitive

Start with one-shot relative timers:

- monotonic clock only;
- no unread expirations;
- no periodic interval;
- no absolute/cancel-on-set semantics;
- explicit remaining time policy;
- target re-arm verifier.

Refuse unread ticks, periodic timers, unsupported clocks, absolute timers, and
ambiguous remaining-time state.

## Phase 4: TCP listener-only Level 4 reconstruction

Add TCP listeners before active TCP connections.

Accepted first subset:

- bind address and port explicit;
- namespace/route explicit;
- backlog explicit;
- reuse flags explicit;
- no accept queue state;
- no active accepted connections claimed;
- target verifier proves listener can accept a new connection.

Refuse active connections, non-empty accept queues, ambiguous socket options,
unknown namespace/route, and TLS/session state.

## Phase 5: Node event-loop Level 4 resources

Use the primitives above to reduce Node Level 3 debt:

- libuv pipes -> Level 4 pipe descriptors;
- libuv eventfd/event loop wakeups -> Level 4 eventfd descriptor or refusal;
- timers -> Level 4 timerfd/timer descriptor or refusal;
- server sockets -> TCP listener descriptor;
- active connections remain refused until active TCP is modeled;
- child/IPC/fs watcher/native addon state remains refused until explicitly
  modeled.

This turns Node runtime-aware proof into generic Level 4 resource work instead of
runtime-specific debt.

## Phase 6: Selected Node Level 5 product subset

Only after enough Level 4 event-loop resources exist, choose a small Node Level 5
subset.

Requirements:

- public `machinen snapshot` / `machinen restore` path;
- no runtime-specific hidden flags;
- target-native verifier;
- Level 4 descriptors for fds/event-loop resources;
- Level 5 register, stack, memory, code, TLS, signal, syscall, thread, and return
  chain handling;
- refusals for native addons, active TCP, inspector/debug, child process
  ambiguity, dirty persistence, and unsupported V8/libuv states.

## Graduation requirements by runtime/workload

### Node

Node can graduate only after libuv/kernel resources and V8/native process state
are explicit:

- Level 4 descriptors for TCP/UDP sockets, listeners, active-connection refusals,
  pipes, event loop wakeups, timers, child/IPC handles, fs watchers,
  credentials/namespaces, readiness, and partial transfers;
- Level 5 proof for registers, stack, heap/private memory, target code/modules,
  TLS, signals, active syscalls, threads, and return chains;
- public `machinen snapshot` / `machinen restore` path with no hidden
  runtime-specific flags;
- refusals for native addons, inspector/debug state, dirty persistence,
  unsupported V8/libuv state, active TCP, and ambiguous child/IPC topologies.

### JVM

JVM can graduate only with an explicit JVM profile:

- safepoints and Java/native thread states are controlled;
- Java frames, native stacks, monitors, JIT/code cache, class metadata, JNI, and
  native libraries have target-native materialization or refusals;
- sockets, timers, signals, TLS, SIMD/FPU, file descriptors, and namespaces are
  covered by Level 4/5 descriptors;
- unavailable JVM profiles, opaque JIT/runtime state, JNI ambiguity, and active
  unsafe threads remain refusals.

### Go

Go can graduate only when runtime scheduler state is no longer opaque:

- goroutine stacks, scheduler queues, channels, timers, netpoller state, cgo,
  TLS, and signals have descriptors or refusals;
- sockets/readiness/partial transfers are Level 4 modeled;
- Level 5 target-native register/stack/memory/code translation exists for the
  selected subset;
- clean static service restart can remain Level 1 by design.

### Python

Python can graduate only when interpreter and extension boundaries are explicit:

- Python frames, GIL/thread state, asyncio/selectors, signals, file descriptors,
  sockets, C extension ABI/state, and module provenance are modeled;
- Level 4 handles kernel resources directly rather than hiding them behind a
  runtime adapter;
- Level 5 handles native stack/register/memory/code if process continuation is
  claimed;
- clean service restart can remain Level 1 by design.

### Databases

Databases can graduate only when logical restore is not standing in for live
process or kernel state:

- active clients/sockets, transactions, WAL/redo/AOF/journals, locks, mmap,
  shared memory, replication, plugin/extension state, file offsets, fsync
  boundaries, and dirty host-mounted state are modeled or refused;
- quiesced logical restore may remain semantic product/proof support, but it must
  not imply Level 4/5;
- live database process continuation requires both Level 4 resources and Level 5
  process translation.

### Ping

Ping's current product support remains Level 2 by design. Ping graduates to Level
4 only with:

- raw or datagram ICMP socket descriptor;
- uid/gid/capability or ping group range policy;
- network namespace, route, and destination policy;
- identifier/sequence/counter linkage to socket state;
- receive queue and in-flight packet policy;
- active `recvmsg` and partial transfer refusal or replay policy;
- target-native verifier proving recreated socket behavior.

## Explicitly avoid first

Do **not** start with these unless the smaller Level 4 primitives are already in
place:

- active TCP connection continuation;
- arbitrary Node process productization;
- JVM Level 5;
- arbitrary Go goroutine/process continuation;
- live database process continuation;
- arbitrary Linux process-image continuation.

These are too broad and should remain refusals or proof until the
Level 4 resource layer is mature.

## Validation expectations

Each phase needs:

- a positive verifier row;
- one or more refusal rows;
- checked summary output;
- docs explaining product support vs implementation level;
- tests proving no success is claimed through source-ISA emulation, sidecar
  output, metadata-only success, or raw cross-ISA checkpoint replay.
