# Goal 004: Phase 2a — pipes Level 4 reconstruction

## Objective

Create the pipe Level 4 graduation slice. Pipes are a small, reusable kernel
resource needed by runtimes such as Node/libuv, but this goal starts as proof and
refusal evidence, not product support.

## Status language

| Field                   | Target while this goal is in proof mode                                            |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `evidenceStatus`        | `proof` for accepted pipe reconstruction; `refusal` for unsafe neighbors           |
| `productSupport`        | `not-yet-supported` for proof rows; `unsupported` for refusal rows                 |
| `implementationLevel`   | `not-implemented` for proof rows; `level-0-fail-closed-discovery` for refusal rows |
| `graduationTargetLevel` | `level-4-kernel-resource-reconstruction`                                           |

## Accepted descriptor shape

Start with bounded pipe pairs:

- exactly one read end and one write end;
- explicit fd numbers or remapping policy;
- explicit flags and close-on-exec state;
- known peer lifetime;
- empty or bounded buffered bytes;
- no waiters;
- explicit readiness state;
- target-native pipe recreation verifier.

## Refusals

Refuse fail-closed for:

- missing peer;
- unknown or closed peer lifetime;
- unknown waiters;
- ambiguous readiness;
- oversized or unordered buffers;
- unsupported flags;
- active partial read/write syscall state.

All refusal rows must keep `productSupport=unsupported` and
`migrationCompleted=false`.

## Graduation requirements

Pipes can move from proof to support only after:

1. pipe descriptors are accepted by the public snapshot/restore path;
2. pipe pairs are recreated target-natively with verified flags and readiness;
3. bounded buffered data is replayed or explicitly refused;
4. all unsafe neighbors remain checked refusals;
5. Node/libuv users consume the generic pipe descriptor rather than a
   Node-specific shortcut.

## Non-goals

- No PTY/TTY support.
- No arbitrary fd graph continuation.
- No hidden runtime-specific pipe state.
