Native binary proof/detection/refusal/support matrix

This tracks simple binary shapes. A fixture proof is not support. Support starts only when detection and fail-closed refusals exist too.

Lifecycle

  1. 1-refused: Refuse first
    The binary shape is not supported. We list why it must fail closed.
  2. 2-proved-fixture: Prove the tiny shape
    A controlled fixture has retained source capture, target restore, both directions, claim guards, and refusal logs.
  3. 2-classified-unaccepted-shape: Classified, not accepted
    A real process state has retained classifier evidence, but it is not accepted until stronger safe-point evidence exists.
  4. 3-detectable-proved-shape: Detect real binaries that fit
    A detector/classifier can identify when a real binary state fits the proved shape and can refuse nearby unsafe state.
  5. 4-supported-subset: Support only the detected subset
    The detected subset is supported; everything outside the detector remains refused.

Support rule

Support requires stage 4: retained proof + detector/classifier + fail-closed refusals. Stage 2 proof alone is not support.

Claim guard

  • arbitrary process restore claimed: false
  • raw VM replay used: false
  • source-ISA emulation used: false
  • metadata-only success: false
